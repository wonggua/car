# car：STM32 小车课程设计总工程

**入口：`car.uvprojx`；烧录文件：`car.hex`。** 基于工作区学生版实验 27 工程结构、原标准库和驱动，结合实验 04–24 的电机、循迹、测距、避障、舵机、寻光、报警和遥控代码整合。

目标为工作区原理图所示 **4WD_STM32_V1.0 / STM32F103C8T6**，8 MHz 外部晶振、72 MHz 系统时钟、64 KB Flash、20 KB RAM。原课程资料未修改。

## 1. 烧录后开始运行

1. 在串口下载工具中选择本目录 **car.hex**，完成下载并校验。
2. **BOOT0 恢复为 0，按 RESET 或重新上电。** 不要只完成下载而不切回运行模式。
3. 小车上电默认停车。正常待机蓝灯慢闪；故障为红灯闪烁。低电压声音报警默认关闭，但不因低电压锁定电机，电机仍需正常的底板供电。
4. 打开下载串口的串口助手，**9600、8N1**，可看到每秒一次的运行状态；关闭下载工具对串口的占用后再连接助手。蓝牙模块也使用 9600、8N1（模块自身串口波特率须一致）。
5. 首次先架空车轮，发送 `1` 验证前进方向，发送 `0` 停车。电机接线反接时，应对照原组装教程修正接线后再落地测试。

电脑串口和手机蓝牙使用同一组命令。手动方向命令发送一次即持续运动，不再因 800 ms 未刷新而停车。发送 `X`、`0` 或 `@STOP`（带换行）停车；换向或切换模式也会更新运动状态。松开按钮时，上位机需主动发送停车指令；通信中断本身不会停车。

## 2. 十种模式在一个固件中切换

选择模式会先停车。自动模式需要再发送 `R` 或短按板载按键启动。

| 模式编号 | 单字符选择 | 模式 | 行为 |
| --- | --- | --- | --- |
| 0 | `M` | 手动遥控 | 前进、后退、原地左右转、弧线左右转、停车 |
| 1 | `T` | 四路黑线循迹 | 差速转向；短暂丢线按最后方向补救，持续丢线向两侧限时搜索，重新见线即恢复 |
| 2 | `U` | 超声波避障 | 前方小于 250 mm 或无有效回波时边后退边扫描，转向后继续避障 |
| 3 | `I` | 红外避障 | 左侧有障碍向右避让，右侧有障碍向左避让 |
| 4 | `C` | 红外+超声波综合避障 | 舵机扫描选路，同时排除红外检测到障碍的方向 |
| 5 | `F` | 超声波跟随（附加） | 目标 300–1500 mm 时接近，80–180 mm 时后退，180–300 mm 内停车 |
| 6 | `L` | 寻光（附加） | 向检测到光的一侧转；双侧有光前进；无光停车 |
| 7 | `G` | RGB 闪烁（附加） | 红、灭、绿、灭、蓝、灭，每步 500 ms，不驱动电机 |
| 8 | `Z` | 测距与信息显示 | 不驱动电机，通过串口持续输出距离及状态 |
| 9 | `P` | PS2 手柄 | 方向键或左摇杆控制，松开停车 |

所有模式均采集电池电压、循迹、避障和寻光信号；超声波以不小于 65 ms 的间隔测量。RGB 模式也受故障状态优先级影响。

**板载 PA8 按键：**短按启停当前模式；长按 1 秒切到下一模式并保持停车。按下消抖后先停车，松开时才完成短按动作。手动模式短按启动不会自动前进，仍需方向命令。模式编号通过串口状态查看。

## 3. 遥控和设置命令

### 单字符：立即执行，不需要换行

| 指令 | 动作 |
| --- | --- |
| `1` 或 `W` / `w` | 前进 |
| `2` 或 `S` / `s` | 后退 |
| `3` 或 `A` / `a` | 原地左转 |
| `4` 或 `D` / `d` | 原地右转 |
| `5` | 弧线左转 |
| `6` | 弧线右转 |
| `0` 或 `X` / `x` | 停车并取消运行 |
| `R` | 启动当前模式，舵机回中 |
| `H` | 蜂鸣 150 ms |
| `?` | 输出一次状态 |

兼容实验 27 的原始字节 `0x01`–`0x06` 控制方向，`0x00` 停车。字母模式命令区分大小写：模式用大写。手动方向命令会自动转入模式 0。未知单字符会停车。

### 设置帧：以 `@` 开始，以回车或换行结束

```text
@MODE=1
@SPEED=3000
@RUN
@STOP
@STATUS
@SERVO=90
@BEEP
@MOVE=1
```

- `MODE=0..9` 选择模式。进入模式 9 后可直接使用手柄，其他模式切换后停车。
- `SPEED=3000..6000` 设置非循迹模式驱动轮基准 PWM（30%–60%，默认 5000 即 50%）。`SPEED=0` 将两轮输出设为零，其他越界值返回 ERR 并停车。转向允许内轮停转或反转，PS2 摇杆按左右轮分别限幅。
- `SERVO=20..160`：舵机角度；先停车再转动。自动模式启动时回到 90°。
- `MOVE=0..6`：与上面的数字方向指令一致，同样保持运动直到收到停车等指令。
- 合法设置返回 `OK`，非法设置返回 `ERR` 并停车。超长帧或超时帧整帧丢弃，不会把尾部数字误当运动指令。

手机可以使用可配置按键的蓝牙串口 APP。这里保证与实验 27 的数字/原始字节协议兼容；未声称兼容未提供协议的厂商重力感应 APP。

**红外遥控（附加）：**沿用实验 24 的 NEC 指令码：64 前进、25 后退、7 左转、9 右转、22 弧线左转、13 弧线右转；21停车、12鸣笛、94灭灯，其余未映射键停车。方向保持执行，松开后不会自动停车，需按其他键停车。不同遥控器码表需要调整 `App/main.c`。

## 4. 信息输出及排错

每秒上报、`?` 和 `@STATUS` 均按当前模式返回同一格式，有线串口、蓝牙和 Wi-Fi 使用相同字段。每行都有模式 `mode`、运行开关 `run`、电池电压 `mv`、低电量标志 `bat`、故障码 `fault` 和报警声音开关 `alarm`。可驱动车轮的模式还显示设定速度 `speed` 和左右轮实际下发的 `pwm`。

| 模式 | 专属状态字段 |
| --- | --- |
| 0 手动遥控 | `cmd` 当前运动指令，`rcode` 最近的 NEC 红外遥控键码 |
| 1 循迹 | `line` 四路黑线位图 |
| 2 超声波避障 | `mm valid servo scan` 距离、前向有效标志、舵机目标角度、扫描阶段 |
| 3 红外避障 | `ir` 左、右红外避障探头 |
| 4 综合避障 | `ir` 及 `mm valid servo scan` |
| 5 超声波跟随、8 测距 | `mm valid servo` |
| 6 寻光 | `light` 左、右光敏探头 |
| 7 RGB 闪烁 | `led` 灯光总开关，`rgb` 最近下发的颜色位图（红=1、绿=2、蓝=4、灭=0） |
| 9 PS2 手柄 | `ps2 pid keys lx ly` 及 `PS2diag` 诊断（回中策略、掉线计数、轮询计数与原始帧） |

发送 `I?` 可立即查看红外避障探头。例如，左侧检测到障碍且小车处于停车状态时，可能收到下面这行。

```text
mode=3 run=0 mv=7800 bat=0 fault=0 alarm=0 speed=5000 pwm=0,0 ir=1,0
```

| 字段 | 含义 |
| --- | --- |
| `mode/run` | 模式编号 / 运行开关 |
| `mm/valid` | 最近距离（毫米）/ 可否用于前方运动控制；valid=0 时 mm 不可作为当前距离 |
| `mv/bat` | 电池电压（毫伏）/ 低电量报警标志（仅声音提示，不限制电机） |
| `fault` | 0 正常；1 实际系统时钟不是 72 MHz；2 ADC 无有效结果（启动约 320 ms 内也会出现） |
| `line` | 四路黑线位图：bit0=循迹4/PB10（左外）、bit1=循迹3/PC15（左内）、bit2=循迹2/PC13（右内）、bit3=循迹1/PC14（右外）；1 表示黑线 |
| `ir` | 左、右避障；1 表示检测到障碍 |
| `light` | 左、右寻光；1 表示检测到光 |
| `servo` | 舵机角度；偏离 90° 时 valid=0，避免把侧向距离当作前方距离 |

低电压仅报警：低于6.8 V置bat=1，开启声音报警后蜂鸣器每秒响200 ms；达到7.0 V解除。不改变运行状态、速度和电机指令。ADC无效与时钟故障仍停车。电压按原理图20 kΩ/10 kΩ分压计算；上车需核对实测电压。

黑线极性默认按实验 17 的“单侧低电平时转向该侧”设置为低电平有效。先在黑线和白底上观察 `line`，若实际模块输出相反，修改 `App/car_config.h` 的 `TRACK_BLACK_LEVEL`。这是传感器输出极性校准，不改变引脚映射。

## 5. 编译与文件

用 Keil 打开 **`car.uvprojx`**，目标名称 `car`，编译器 ARM Compiler 5，STM32F1xx_DFP 2.4.0。点击 Rebuild，最新 HEX 位于 **`Objects/car.hex`**。

也可运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

脚本默认使用本机 `E:/keil5/32/UV4/UV4.exe`，编译成功后同步根目录 `car.hex`。其他电脑可通过 `-Keil "完整UV4.exe路径"` 指定位置。脚本不会自动烧录。

- `App/car_config.h`：速度、阈值、极性、波特率。
- `wenchao_lib/`：原例程驱动及明确记录的必要修正。
- `Reference/`：修改前驱动及来源记录，未加入编译。
- `引脚与资源核对.md`：所有资源对应关系及冲突处理。
- `验证与验收.md`：已完成验证与实车验收顺序。

## 6. 指导书的功能边界

指导书第 1–2 页明确要求的电机、循迹、超声波、避障、蓝牙和多功能整合均已实现。你确认没有连接 LCD/OLED，因此本工程通过串口/蓝牙输出信息，没有擅自占用循迹接口接显示屏。

指导书第 2 页另外介绍 Wi-Fi/微信控制、APP 重力感应和“灭火”等商品扩展能力。现有例程未给出微信平台协议或灭火执行器接线，故本工程未虚构这些功能。原理图上的 Wi-Fi 与蓝牙共用 USART2；若使用已配置好的透明传输 Wi-Fi 模块，可传输本工程同一串口协议，不能与蓝牙同时驱动共用串口。云端微信服务、手机重力感应界面及未提供的灭火硬件不在已实现功能中。

本次交付是已编译、已完成软件逻辑测试的工程，尚未进行实车联调或 Proteus 电路仿真，不能据此保证不同底板版本直接运行一致。

实际安装从左到右为循迹4、3、2、1，分别连接同编号底板接口。停车状态下，仅一路探头检测黑线时，循迹4/3/2/1的 line 应分别为1/2/4/8；中间3和2同时检测黑线时为6。

实际左右映射：红外避障2/PA4为左、避障1/PA6为右；寻光2/PA5为左、寻光1/PB3为右。状态 ir 和 light 仍按左、右顺序输出。

## PS2 手柄控制

基于工作区 `PS2解码通讯及例程V1.93/SPI(1)/PS2/Crtl` 的轮询和按键协议移植。例程使用 HAL/SPI1，与现有底板引脚不兼容；本工程沿用标准库，改为底板 PS2 接口上的 GPIO 模拟通信，不占用额外定时器。原始文件保存在 Reference/PS2_example_*。

| 底板 PS2 接口编号 | 信号 | MCU / 电源 |
| --- | --- | --- |
| 1 | CLOCK / CLK | PB15 |
| 2 | ATTENTION / ATT / CS | PB14 |
| 3 | VCC | +5V（按底板设计，接收器需支持此供电） |
| 4 | GND | GND |
| 5 | CMD / DI（接收器输入） | PB13 |
| 6 | DATA / DO（接收器输出） | PB12 |

按接口编号和信号接线，不能凭插头方向猜测。ACK 不使用。PB12 输入上拉，PB13/14/15 输出。CLOCK 空闲高，低位先发。手柄模式每 10 ms 轮询一次，其他模式每 20 ms 检查一次，支持停车时按 START 切入。校验失败后在该轮询起点后 5 ms 补读一次。普通轮询发送 9 字节时钟，扩展帧发送 21 字节时钟。

使用步骤：
1. 断电连接接收器，打开手柄并完成它与接收器的无线配对。
2. 上电等待至少 1 秒。发送 `P` 或带换行的 `@MODE=9` 进入手柄模式，也可用板载按键切换。停车时点按手柄 START 也可切入。
3. 在模式 9 发送 `?` 查看连接状态。`ps2=1` 表示最近 60 ms 内收到有效的接收器数据，`pid=65` 为数字模式，`pid=115` 或 `121` 为模拟模式。
4. 松开方向键并让左摇杆回中一次，然后操作：方向键上/下前进后退，左/右原地转；模拟模式的左摇杆支持前后和差速转向，回中死区24，最高输出受当前speed限制。方向键优先于摇杆。数字模式可直接用方向键；左摇杆不响应时按手柄 ANALOG 键切换，观察pid/lx/ly。
5. 松开方向键、摇杆回中即停车，下一次给方向即可继续行驶。SELECT、叉键或串口 `X`/`0` 也可停车。留在模式 9 时，松开按键并回中一次后，下一个方向指令即可重新起步。要结束手柄控制，发送 `M` 切回手动模式。

有效帧在当轮主循环更新电机指令，松键或摇杆回中的有效帧会把左右轮 PWM 置零。零星坏帧允许补读，距最后一帧有效数据满 60 ms 后，在下一次控制检查时撤销轮速。已解锁的手柄恢复通信后，按新帧的方向继续控制。串口状态的 `linkGaps` 是本次上电后手柄控制检测到的超时次数，`pwm=左,右` 是最近一次写给左右轮的有符号 PWM 指令。若接收器在无线断连后仍重复返回旧的有效帧，仅靠此协议无法识别。串口方向指令会切回手动模式。

新增状态字段：`ps2` 数据是否新鲜有效；`pid` 模式ID（十进制）；`keys` 按下按钮位图（十进制）；`lx/ly` 左摇杆原始值0–255，中位约128。未收到有效数据时不要用旧的keys/lx/ly判断当前手柄状态。

## 红外遥控、低电量提示及舵机扫描避障

红外遥控接收器信号为PA1，底板红外遥控插座供电为3.3V。不要与左右红外避障传感器混淆。协议为实验24的NEC标准地址反码格式，接收始终启用，方向键会切至手动模式。按一次保持方向，松开不自动停车；21或其他未映射有效按键、串口X停车（12鸣笛、94灭灯不停车）。重复帧只有在最近180 ms内存在已接收的有效指令时才生效。

| 原始命令码（十进制 / 十六进制） | 动作 |
| --- | --- |
| 64 / 40 | 前进 |
| 25 / 19 | 后退 |
| 7 / 07 | 原地左转 |
| 9 / 09 | 原地右转 |
| 22 / 16 | 弧线左转 |
| 13 / 0D | 弧线右转 |
| 21 / 15 | 停车（用户确认） |
| 12 / 0C | 鸣笛150 ms，不改变运动 |
| 94 / 5E | 关闭RGB三色灯，不改变运动 |
| 其他未映射有效命令 | 停车 |

状态新增rcode，显示最近收到的原始NEC命令（十进制）；初始255。遥控器按键布局或编码不同，请先架空车轮，按键后查看rcode，再匹配码表；不支持任意遥控协议。

超声波模式发送 U 再发 R，综合模式发送 C 再发 R。前方不足 250 mm 或无有效前向测距时，小车以 30% 占空比后退，舵机先向左、再向右测距，每侧最多等待 900 ms。随后舵机回中，车身向距离较大的一侧原地转向约 350 ms。两侧距离相同或均无回波时交替选向。综合模式优先避开红外检测到的障碍。若前方仍受阻，继续下一轮避障。

左右扫描角度按默认安装设为150°/30°，实际舵盘安装必须核对：停车后发送@SERVO=150（带换行）观察是否朝左，@SERVO=30观察是否朝右。若相反，在App/car_config.h互换CAR_SCAN_LEFT_ANGLE和CAR_SCAN_RIGHT_ANGLE后重新编译；先确保90°朝车头正前方。状态servo表示目标角度，不是反馈；scan=10/11/13分别表示左测、右测、回中并转向。

低电量报警使用沿用例程的6.8 V阈值和7.0 V恢复值，仅驱动蜂鸣器提示，不停止电机；RGB仍显示当前模式状态。默认速度5000、串口持续运动、PS2松开停车，以及传感器实际左右映射均保留。

## 鸣笛、灭灯与停车

| 功能 | 红外rcode（十进制） | 蓝牙／有线串口文本命令 |
| --- | --- | --- |
| 停车 | 21 | X 或 0 或 @STOP |
| 鸣笛150 ms | 12 | H 或 @BEEP |
| 关闭底板RGB三色灯 | 94 | O（大写字母，不是数字0）或 @LIGHT=0 |
| 恢复灯光 | 未分配 | @LIGHT=1 |

所有@开头命令末尾发送换行。蓝牙APP按键设为ASCII文本：鸣笛H、灭灯O、停车X。关灯在模式切换后保持，恢复后按当前模式显示；重启默认恢复灯光。关灯不停止电机、不静音低电量报警，也不能关闭硬件电源灯、接收器灯和传感器指示灯。状态led=0表示关闭RGB输出，led=1表示按当前模式显示。红外鸣笛键长按产生重复帧时延长鸣笛，松开后约150 ms结束。


模式 9 状态记录末尾的 `PS2diag` 显示累计轮询次数 polls、通过校验的帧数 good、最近一帧原始字节 raw（十六进制）。第二字节为 ID，第三字节应为 5A。手柄关闭、开启、按住方向上时可分别记录一行进行对比。

### 低电量报警与手柄回中

按一下三角键切换低电量报警声音，或经串口、蓝牙发送 @ALARM=0 静音、@ALARM=1 恢复，命令末尾加换行。alarm=0 表示已静音，bat=1 仍表示低电量；手动喇叭可用。复位后默认静音。

进入模式 9 时先松开方向键和摇杆。若启动时左摇杆偏离默认中点，本次运行只用方向键（padOnly=1），松开即停。偏心摇杆可单独校准：按 SELECT 停车，松开左摇杆，按住 L1 再点按 START，程序将此位置作为本次运行的中点。

### 四路差速循迹（模式 1）

发送 `T` 选择循迹，发送 `R` 启动。居中时两侧同速前进，默认 PWM 为 30%，可用 `SPEED=2500..3500` 调节。向左微调或转弯时，左侧 PWM 为 0，右侧正转。向右时左右互换。单个内侧探头持续见线 20 ms 后开始微调，外侧驱动轮 PWM 最高为 35%，回中立即恢复同速。同侧内外探头同时见线或仅单个外侧探头见线时，外侧驱动轮以 50% PWM 转弯。

四路全白时，从最后见线起的前 250 ms 内，居中或仅内侧探头见线后以 25% PWM 直行，偏向一侧转弯后则沿该方向补救。满 250 ms 后，向最近确认偏线的一侧搜索，无方向记录时先向左。搜线转向时内侧 PWM 为 0，外侧以 50% PWM 正转。满 600 ms 换向，满 1650 ms 停轮等待，任一阶段重新见线即恢复循迹。
## ESP-01S 热点直连

断电插入底板的 2×4 WIFI 座，按模块 TXD 与插座 1 脚 wifi_tx 对齐。选择器 BLUE_WIFI 的 1–2 接通 Wi-Fi，2–3 接通蓝牙。Wi-Fi 座 2 脚为 WIFI_GND，3、7 脚接 3V3，8 脚 wifi_rx 接 PA2，1 脚 wifi_tx 接 PA3。底板蓝牙座的供电为 5 V。原理图见课程资料的“03. 原理图/4WD_STM32_V1.0_crack.pdf”。

给 STM32 烧录 car.hex，复位。模块需已装支持 SoftAP、TCP server、主动 +IPD 接收的 ESP8266 AT 固件，AT 口在模块 TXD/RXD，115200、8N1，热点 DHCP 已启用。STM32 的有线控制台仍是 9600、8N1。看到 wifi: STM32-Car TCP 192.168.4.1:8080 ready 后即可连接。连续出现 AT timeout 时，检查选择器、模块方向、AT 固件及波特率；failed command 后面是模块拒绝的命令。

手机或电脑连接热点 STM32-Car，密码 Car8266wifi，手机选择保持连接。用网络助手建立 TCP 客户端，目标 192.168.4.1，端口 8080。首个 TCP 客户端可以控制和接收状态，先断开旧客户端再换设备。串口和 Wi-Fi 共用控制协议，连接后自动回传每秒状态，发送 ? 可立即查询。发送 1 前进、2 后退、3 左转、4 右转、X 停车。发送 @SPEED=3000 加换行调速；发送 P 切回 PS2 手柄模式。连接和查询状态均保留当前驾驶模式。Wi-Fi 方向指令会切到手动模式并保持运动，断开 TCP 前先发送 X。

car.hex 是蓝牙与 Wi-Fi 合并固件。上电默认 Wi-Fi，Keil 工程仅保留 car 合并目标。停车后将底板选择器拨至所用模块，通过有线串口发送 `$BT` 或 `$WIFI` 并换行；状态行 radio=BT / radio=WIFI 显示当前选择。蓝牙使用 9600，ESP-01S 使用 115200。切换时撤销当前运行指令，重新上电后恢复 Wi-Fi。执行 ./build.ps1 导出 car.hex。首次实车验收先架空车轮，核对 ? 状态、1 前进、X 停车和 P 手柄模式。

### 让小车加入手机热点

打开手机的 2.4 GHz 个人热点，使用 WPA2 密码。烧录新版 car.hex 后，通过 STM32 有线控制台（9600、8N1、文本、每行加换行）依次发送 `$SSID=热点名称` 和 `$PASS=热点密码`，等号后直接填实际内容，不加引号。含中文的名称用 UTF-8 发送。连接成功后，串口显示 `wifi: phone hotspot TCP <小车IP>:8080 ready`。在开热点的手机或连接同一热点的电脑上，用 TCP 客户端连接该 IP 的 8080 端口，发送 ? 验证状态。方向、停车和切换模式指令与小车自建热点时相同。若看到 +CWJAP:2，检查密码；+CWJAP:3 表示没有找到热点。串口发送 `$AP` 并换行可恢复自建热点。STM32 复位后默认自建热点，需要重新发送热点名称和密码。
